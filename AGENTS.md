# Agent instructions

Read this before changing anything in this repository. It states the invariants
that must not be broken and the checks that must pass. The reasoning behind them
is in [docs/00-experimentation-guide.md](docs/00-experimentation-guide.md); read
that too before designing a new experiment.

This is a **measurement harness**. Its output is numbers that people will act on,
so a silently wrong number is the worst possible failure. Every rule below exists
because a plausible-looking wrong number was produced during the first study.

## Environment

```bash
uv venv --python 3.12          # never install into system Python
uv pip install -e .            # offline path: build, baselines, all non-LLM metrics
uv pip install -e ".[embeddings]"   # optional neural embedding backend
```

Run everything through `.venv/bin/…`. Credentials live in `.env`
(`OPENROUTER_API_KEY`); never hardcode or echo a key.

## Before you claim you are finished

```bash
.venv/bin/python -m pytest tests/ -q      # must pass
.venv/bin/ruff check src/                 # must be clean
.venv/bin/python experimental-notes/build.py   # must be deterministic
```

If you touched the report generator, build twice and confirm the HTML is
byte-identical. A non-deterministic build usually means an unsorted dict or a
`hash()` leaked in.

Every page carries the time it was generated, so pin it while checking or two
builds either side of a minute boundary will differ in one character of every
page and the check will report a difference that is not one:

```bash
SOURCE_DATE_EPOCH=1000000000 .venv/bin/python experimental-notes/build.py
```

Build twice that way, compare, then build once more without the variable so the
committed HTML states when it was actually generated.

## Training a method on the cluster

Read [docs/09-cluster-training-config.md](docs/09-cluster-training-config.md) before writing a
training script. It records the measured memory ceiling, the required batch and sequence
settings, and the three training variants. Two points that are easy to get wrong:

- **Use 4-bit NF4 on `meta-llama/Llama-3.1-8B-Instruct`, batch size 1, max length 768.** The
  128k-vocab logits tensor, not the weights, sets the ceiling. bf16 peaks at 22.6 GB of 23.5 and
  dies the moment another process joins the GPU; 4-bit peaks at 19.1 GB and survives one. Every
  method uses the same quantisation so it is a constant of the study rather than a difference
  between its columns.
- **There are three training variants, not one**: `target_lm` (room and topic only),
  `target_lm_paired` (plus a retrieved same-cell source post), and `target_lm_aspect` (plus the
  aspects the post foregrounds). Run every method against all three and report the variant with
  every number. A score without its variant is not interpretable.

## The NDIF scale arm

`steering_ndif` runs the local steering construction on NDIF-hosted 70B and 405B.
Two things about it are easy to get wrong:

- **A remote column is not comparable with a local column.** Every local method
  runs under 4-bit NF4 so quantisation is a constant of the study; NDIF serves its
  own precision, so that constant does not cover this arm. `load_in_4bit` is
  recorded as `None` rather than `False` precisely so the two cannot be pooled by
  accident. The remote column is a scale contrast against the local *steering*
  column, and nothing else.
- **Vectors do not transfer between models.** A local artifact has 4096 columns;
  70B's residual stream is 8192 wide and 405B's is 16384. The scale arm fits its
  own artifact with `fit_steering_ndif`. The `base_model` guard enforces this.

See [docs/11-ndif-steering.md](docs/11-ndif-steering.md), including why the pinned
*base* models cannot be used (no chat template, which would reintroduce the Study 3
item 1 wrapping confound).

## Hard invariants

Breaking any of these produces wrong numbers without raising an error.

### 1. Exemplars come from train; references come from the scored split

`TransferTask.exemplar_ids` must only ever contain train-split posts.
`target_reference_ids` must only contain posts from the split being scored. This
is the entire leakage-control argument. If you add a split or change
`build_dataset.py`, preserve it.

### 2. Every column in a comparison is averaged over the same cells

A column's own coverage must never define the comparison base. The results table
restricts to cells that every *system* column covers; any reference column scored
on fewer prints its own count as a superscript. Violating this once made the
oracle look worse than doing nothing.

### 3. A difference is only a finding if the intervals separate

Bootstrap over cells. If the intervals overlap, the comparison is **not
resolved** and must not be stated as a result. The resolution table in the report
is generated by the overlap test, not written by hand. Prose states only what the
table supports; point estimates belong in tables and figures.

### 4. Distributional statistics need a minimum pool size

Below it, return `NaN` and exclude the cell rather than contributing noise. MMD
on pools of 2–4 returns negative values and outliers that dominate any average.
`MIN_MMD_POOL` and `MIN_POOL` (TRM) exist for this; a new metric needs the same
guard and a test pinning it.

### 5. Multi-candidate sampling requires the variant in the cache key

`LLMClient._cache_key` includes a `variant` index. Without it, draws 2..k are
served the identical cached completion and the "candidate pool" is k copies of one
post. Any change to the caching layer must preserve this.

### 6. Failures are recorded, never dropped

An LLM refusal or persistent error returns `ok=False` with an empty string, and
one `TransferOutput` is still emitted per task. Silently dropping failures biases
every distributional metric toward whatever succeeded. The `degeneracy` metric
surfaces the rate.

### 7. TRM values are only comparable within one base distance

TRM is a meta-metric over a pairwise distance (cosine in the harness embedding
space). The base distance is recorded in every report under
`notes.<fn>.trm.pairwise_distance` / `.distance_space`, and the space itself
under the top-level `embedding_space`. It must be stated alongside any value.
Switching the embedding backend invalidates every prior TRM number.

The space is selected on `evaluate` (`--embedding-backend`, `--embedding-model`,
`--embedding-dim`) and applies to every embedding-based metric at once. Because
values from two spaces are not comparable, a report is named after the space it
was computed in whenever that space is not the default: the default keeps
`report.<split>.json` and anything else becomes
`report.<split>.<slug>.json`, e.g. `report.heldout.embeddinggemma-300m-d256.json`.
Do not defeat this by passing `--report-tag` to force two spaces into one file.
`EmbeddingSpace` memoises encodings per text; that cache must stay exact, since
a backend that encoded a document differently depending on its batch would make
every score depend on evaluation order.

### 8. Splits are deterministic and append-safe

`blake2b(post_id, seed)`, never a shuffle and never Python's salted `hash()`.
Adding new scraped data must not reshuffle existing assignments.

## Reporting rules

The report in `experimental-notes/` is generated from the run JSON by
`build.py`. Never hand-edit the HTML.

- **Figures read from the report**, never from transcribed numbers. Counts and
  ranges quoted in captions are computed, not typed.
- **Axis limits derive from the data.** A hardcoded limit clipped the largest
  points off the plot when the run scaled.
- **Every comparison figure shows all three references** (`identity`,
  `shuffle_control`, `target_sample`), each labelled with its role. Dataset-only
  figures are exempt.
- **Text must fit the viewBox.** `text_block()` wraps; the layout audit in the
  guide catches overflow.
- **Before writing any count or "in every / all" claim into prose, compute it.**
  A sentence that was true for an earlier run silently becomes false.

Publish with `scripts/publish_report.sh`. Two non-obvious constraints are baked
in: `aws s3 cp --recursive` segfaults against the Wasabi endpoint, so uploads go
per-object via `s3api put-object`; and content types must be set explicitly or
browsers download the HTML instead of rendering it.

## Writing style for reports and docs

The audience is a technical collaborator, not a specialist in this harness.

- Formal register, complete sentences, no split clauses or em-dash asides.
- Plain vocabulary over jargon. Say "outputs are too similar to each other", not
  "homogenisation". Avoid *register, dispersion, instrumentation, provenance,
  residualisation, meta-metric* in reader-facing prose; define them if unavoidable.
- Keep interval and significance discussion out of the running text. It belongs in
  the resolution table and the error bars.
- Limitations live in the limitations section, not scattered through the results.
- State useful outcomes plainly. Do not hedge a supported finding.

## Adding a component

**A transfer function** implements `run(tasks, corpus) -> list[TransferOutput]`,
returns one output per task including on failure, and is registered with
`@register("name")`. Add the import to `transfer/__init__.py`. It is then scored
by the identical metric suite on identical splits with no further work.

**A metric** implements `score(transfer_fn, outputs, ctx) -> MetricResult`,
returns cell-level scores, declares `directions` (+1 higher better, −1 lower
better, 0 diagnostic), and is registered with `@register("name")`. Before
considering it finished, check that it separates the three baselines; a metric
that scores `shuffle_control` as highly as `target_sample` is style-indexed and
must not be reported.

## Scaling before asking for data

Coverage, not corpus size, is the binding constraint. Exhaust these first:

1. `--split heldout` merges validation and test for scoring. Both are already out
   of every exemplar pool, so this is leakage-free and roughly doubles references
   per cell.
2. `--n-samples k` draws k candidates per source post, enlarging the candidate
   pool by k with no new data. This is what the TRM paper prescribes and it is
   the only way to observe within-model variation.

Together these took TRM coverage from 5 cells to 10 and resolved three previously
unresolved comparisons.
